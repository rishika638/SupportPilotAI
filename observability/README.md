# SupportPilot AI ? Observability

Prometheus + Grafana stack for local and production monitoring.

## Files

| File | Purpose |
|---|---|
| `prometheus.yml` | No-auth local-dev scrape config (used when `METRICS_TOKEN` is unset) |
| `prometheus.yml.tmpl` | Template rendered at container startup via `envsubst`; injects `METRICS_TOKEN` as a bearer token |
| `docker-compose.observability.yml` | Prometheus + Grafana services |
| `grafana/dashboard.json` | Pre-built operational dashboard |
| `grafana/provisioning/datasources/prometheus.yml` | Auto-provisions Prometheus datasource in Grafana |
| `grafana/provisioning/dashboards/dashboard.yml` | Auto-provisions the dashboard from the mounted JSON file |

## Required Environment Variables

| Variable | Description | Required |
|---|---|---|
| `METRICS_TOKEN` | Bearer token for the `/metrics` endpoint ? must match the value set on the API server | Yes (production) |
| `GF_ADMIN_PASSWORD` | Grafana admin password | Yes |

**Never commit real values.** Use a `.env` file (git-ignored) or your secrets manager.

## Local Setup

```bash
# 1. Copy and fill in values
cp .env.example .env
# Set METRICS_TOKEN and GF_ADMIN_PASSWORD in .env

# 2. Start the API first (so Prometheus can scrape it)
docker compose up -d

# 3. Start observability stack
cd observability
METRICS_TOKEN=<your-token> GF_ADMIN_PASSWORD=<your-password>   docker compose -f docker-compose.observability.yml up -d
```

Or with a `.env` file in the `observability/` directory:

```bash
# observability/.env  (git-ignored)
METRICS_TOKEN=your-token-here
GF_ADMIN_PASSWORD=your-grafana-password
```

```bash
cd observability
docker compose -f docker-compose.observability.yml --env-file .env up -d
```

## Endpoints

| Service | URL | Notes |
|---|---|---|
| Prometheus | http://localhost:9090 | No auth on Prometheus UI itself |
| Grafana | http://localhost:3001 | Login: `admin` / `$GF_ADMIN_PASSWORD` |
| API Metrics | http://localhost:3000/metrics | Requires `Authorization: Bearer <token>` when `NODE_ENV=production` |

## How Prometheus Auth Works

Prometheus does not expand environment variables in its YAML config file natively.
The `docker-compose.observability.yml` overrides the container `command` to:

1. Install `gettext` (provides `envsubst`) via `apk`
2. Run `envsubst < prometheus.yml.tmpl > /tmp/prometheus.yml` ? substitutes `${METRICS_TOKEN}`
3. Start Prometheus with `--config.file=/tmp/prometheus.yml`

The rendered config uses Prometheus's native `authorization` block:

```yaml
authorization:
  type: Bearer
  credentials: "<token>"
```

If `METRICS_TOKEN` is empty (local dev without auth), the credentials field is blank
and Prometheus scrapes without a token ? matching the API's behaviour when
`NODE_ENV != production`.

## Production (Render)

`METRICS_TOKEN` is auto-generated by `render.yaml` (`generateValue: true`).
Set the same value as `METRICS_TOKEN` in your Prometheus/Grafana Cloud configuration
or self-hosted Prometheus environment.
